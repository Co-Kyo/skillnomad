# 案例交代：scenario-pipeline 如何用 skillnomad 建起来

> **写给谁**：想知道"范式在真实长管线里到底改变了什么"的人——不宣传，只交代。本页每个断言附复算方式；做不到的，如实写在对应位置。

scenario-pipeline（下称 SP）是我们团队自己的 11 步知识管线 skill，也是目前唯一完整走过"plaintext → 范式"全程的案例。2026-09 我们对本页内容做过一轮取证＋证伪审查（每个结论跑命令验证，攻击不倒的才留下），以下就是存活的部分。

## 一、源码怎么建起来的

SP 源码分三面（按读者时刻组织，不按技术分层）：

```text
src/
├── steps/<NN>-<id>/step.ts      # 11 份步骤声明：链式骨架（实测 0% 散文，92-96% 声明）
├── steps/<id>/content.ts        # 该步的散文正本（提示词、判据）——与骨架物理分离
├── packages/<name>/             # 5 个内容包：skill.json 清单＋blocks 散文块（跨步共享的方法论）
├── artifacts.ts                 # 路径单源：所有资产/产物路径只写这一处
├── skill-decl.ts                # 向框架声明：contracts 注册表、模块挂接、策略
└── skill.ts → createSkillFromModel → npx skillnomad build
```

框架拿到的每一句承诺都是**数据**：`dependsOn` 链、`phases` 阶段、`.checkpoint()` 检查点、`scope` 角色——构建期校验（断链/成环/跨步私有/发布布局）拿这些数据查表报错，而不是读散文。路径同步点从迁移前的 4-7 处字面量收敛到 `artifacts.ts` 一处，且资产表↔登记表由测试锁成一一对应。

**诚实限定**：清晰是**声明层**的清晰。散文本身搬进了 `content.ts`——对陌生读者，读 TS 里的散文不比读 markdown 里的散文快；首次了解"某步做什么"，最快的仍是编译产物 `steps/<NN>-<id>/step.md`（一步一份）。范式的优势面在**维护与演化**：改东西时，影响面是机器可查的。

## 二、如何对一步做质量扫描与定向优化

这是使用范式后最实际的收益：长流程被拆成局部后，你可以只针对某一步做评估和打磨，而不必在整篇里翻找。以 evaluate-pool 步为例，一条完整回路四步走完：

```bash
# 1. 取局部：只拿这一步的散文（内容包一行装载；或直接读该步产物 step.md）
npx tsx -e "import {loadPackage} from 'skillnomad';
  console.log(loadPackage('./src/packages/evaluate').body)" > /tmp/step-prose.md

# 2. 扫描：把 /tmp/step-prose.md 交给你的评估手段——人读、或模型评（清晰度、可执行性、歧义）

# 3. 定向优化：只改这一步的源（content.ts / 包块），重建
npm run build

# 4. 验证落点：全产物逐文件比对——15 个文件里唯一内容变化就是这一步，其余逐字相同
```

回路成立的三个前提，都由框架守住（对照手工拆分文件的旧形态，这三件是净贡献）：

1. **局部自足**：该步产物 `steps/<NN>-<id>/step.md` 一份读完整步——域绑定的具体动作（校验哪个字段、按什么阈值）必须在正文里，不能只留"见附录"指针；否则取出来的是断供的半句。
2. **改动可归因**：一个词只有一个源发点，重建后 diff 精准落位；未改源连跑两次逐字节相同——可重放，不是运气。
3. **失同步即红**：改阈值表一个值，回归锁抓红并指名该步；把 A 步私有模块塞给 B 步，构建失败并给出两个步名。旧形态里同一评分制在两个文件各写一份、矛盾了 20 天没人发现。

**当前边界（如实）**：回路闭合在**步粒度**。再往细到**块粒度**（一步内某一条方法块单独评）——内容包的块在源码里已是独立文件（`packages/*/blocks/*.md`），可单独取出，但渲染进产物后块边界对扫描器还不够显性。把块级边界做成机器可读的，记在路线上。

## 三、数字与复算

对照口径：**发布产物 vs 发布产物**（双侧同为纯 markdown，排除 README）：

| | Before（v1.2.0 产物树，2026-08-30） | After（v1.5.2 范式产物，2026-09-19） |
|---|---|---|
| 文件数 | 50 | 31（-38%） |
| 总字符 | 146,723 | 117,563（-20%） |

# 决策文档标准格式（四段）

整篇就四段，标题用下面这四个，别加第五段，也别换顺序。前面不加摘要、后面不加附录。

## 1. 结论

一句话说清"做还是不做"，后面括号里给置信度：高 / 中 / 低。
置信度别凭感觉写——三个角色里有两个立场明确且方向一致才算高；只有一个明确的写中；有角色拒不退让或议题本身缺数据，写低。
结论里的限定条件如果超过一个，说明结论还不可执行，回第一步补讨论。

## 2. 依据

3 到 6 条，每条后面用括号标来源角色：（后端）（产品）（安全）。两个角色都支持的标两个来源。
每一条必须能在分歧表里找到原话出处，找不到就不要写。没标来源的条目按不合格处理。
共识条目优先排前面，但有分歧的条目不要藏。

## 3. 风险

写会真出事的那几条，注明影响面（谁受影响）和能缓解到什么程度。
硬要求：反对意见里最有力的一条必须原样保留，不许省略、不许弱化措辞、不许跟别的条目合并。哪条最有力？看它带不带可验证的前提——"如果 X 不满足，方案会失效"这种比"担心复杂度"有力。这条是整份文档的信用所在，评审的人第一个找它。

## 4. 待决

格式：谁 + 什么时候之前 + 定什么。三样缺一样就是没写完。
待决从"让对方让步的条件"和分歧表里仍分歧的行翻译过来，不要新造议题。
3 条以内，超了说明讨论没收口。已经定了的事不许混进来充数。

---

交稿前扫一遍：四段齐吗？依据每条都有来源吗？最有力的反对意见活着吗？待决每条都能落到人头上吗？
四个问题有一个答不上来就别交。
